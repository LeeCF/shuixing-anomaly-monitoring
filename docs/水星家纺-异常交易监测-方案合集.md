## 1. 目标与范围

### 客户来源与定位

本项目对应客户《水星家纺AI场景_财务》10 场景清单中的 **场景 5「异常交易实时检测」**（风控层）。客户原文要求：三层一起跑（规则 + 统计异常 + 行为画像），输出"异常原因 + 相似历史案例 + 建议动作"，而非"判定异常"四个字。该场景是枢纽——清单中场景 7（合规审查）、场景 9（成本差异分析）均标注"跟场景 5 相通"，做出彩可放大演示价值。

三个 demo 场景均取自客户明确点名的覆盖范围（供应商付款 / 重复付款 / 拆单·临界值行为），刻意各打一层：

| # | 场景 | 主打层 | 客户点名 |
|---|------|--------|---------|
| 1 | 供应商银行账户变更后首笔大额付款 | 画像/行为层 | 供应商付款 |
| 2 | 重复付款 | 规则层 | 重复付款 |
| 3 | 临界值聚集拆单 | 统计+画像层 | 拆单 / 临界值行为 |

### 目标

用一个可演示的 PoC 证明：**AI 不只是"判定异常"，而是给出可执行的决策支持**——异常原因（三层联动）+ 相似历史案例（RAG）+ 建议动作，全部输出为结构化告警卡，展示在 Fiori 风格页面上。

### PoC 范围（严格限定）

- **包含：** 3 张预制告警卡（逼真 JSON 硬编码）+ Fiori 风格交互 Web UI + 模拟检测触发动画
- **不包含：** 真实检测算法、真实 LLM 调用、ERP 接入、生产级权限  
- **架构设计仍预留接缝**：向评委解释"换成真实引擎只需替换数据源和 LLM 适配器"

### 成功标准

演示时能完成以下流程：  
1. 打开列表页，看到 3 条不同类型的告警  
2. 点进某条，看到完整 6 要素告警卡（含 AI 生成的原因分析、Top3 相似案例、建议动作）  
3. 回答评委"这个 Z-score / 集中度评分哪来的"——全部真算，能解释

## 4. 数据设计

### 4.1 数据库表（SQLite）

```sql
transactions   -- 交易流水: id, date, amount, employee_id, vendor_id, 
               --          po_number, invoice_number, created_by, approved_by,
               --          created_at (timestamp)
employees      -- 员工: id, name, dept, role
vendors        -- 供应商: id, name, created_at, bank_account, bank_changed_at,
               --         has_purchase_history, has_receipt_history
historical_cases -- 历史已确认案例: id, type, description, amount, outcome, date
alerts         -- 生成的告警卡: id, alert_no, risk_score, level, card_json, created_at
```

### 4.2 三个 Demo 场景的数据埋法

每个场景：先生成 6-12 个月"正常历史"，再埋入异常——确保三层信号全是真算出来的。

---

**场景 1：供应商银行账户变更后首笔大额付款（画像/行为层主打）**

> 商业邮件诈骗（BEC）最典型模式：攻击者伪冒供应商提交换账信息，新账户首笔就是大额。

- 供应商"S001-XX纺织材料" 有 18 个月正常交易历史
- 在 T-3 天发生银行账户变更（bank_changed_at 字段）
- T 日发生一笔 42 万元付款（历史单笔均值 8 万）
- **三层信号：**
  - 规则层：付款发生在账户变更后 72 小时内
  - 统计层：金额 Z-score = (42-8)/σ，σ 由历史数据真算
  - 画像层：账户变更→首笔付款间隔评分（越短越危险）

---

**场景 2：重复付款（规则层主打）**

> 客户明确点名场景。多套系统孤岛下最易发生：同一笔应付被不同系统/不同经办各付一次。

- 供应商"S002-XX印染" 有正常交易历史
- 存在一笔原始付款：2026-10-10，金额 23.6 万，发票号 INV-2026-8842
- T 日（2026-10-22）又出现一笔：同供应商 + 同金额 23.6 万 + 同发票号 INV-2026-8842，经办人不同
- **三层信号：**
  - 规则层：同供应商 + 同金额 + 同发票号，30 天内出现 ≥2 次，硬命中
  - 统计层：该发票号重复计数 = 2（正常应为 1）；两笔间隔 12 天
  - 画像层：两笔分属不同经办人/不同渠道（跨系统孤岛特征）

---

**场景 3：临界值聚集拆单（统计 + 画像层主打）**

> 员工长期把金额压在审批阈值正下方——本福特定律的典型体现。

- 审批阈值设定为 5 万元
- 员工"E003-王某"过去 6 个月记录：随机分布 1 万-8 万，无明显规律
- 最近 90 天：15 笔付款，13 笔落在 4.7 万-4.98 万区间
- **三层信号：**
  - 规则层：90天内 ≥10 笔落在阈值 ±5% 区间（软触发）
  - 统计层：阈值区间命中率 vs. 历史均值，Z-score 真算；使用滑动窗口检测聚集时间段
  - 画像层：E003 阈值下方累计金额 / 总付款额占比（集中度偏差）

---

### 4.3 历史案例库（RAG 检索用）

预置 8-10 条已确认处置案例，覆盖三个场景类型，含字段：  
`类型 / 描述 / 金额区间 / 处置结果 / 教训摘要`

检索策略（兜底）：场景类型精确匹配 → 金额区间相近 → 关键词余弦相似度，取 Top3。

- [ ] **Step 3: 写最小 FastAPI 应用**

`backend/main.py`:
```python
import json
from pathlib import Path
from fastapi import FastAPI, HTTPException
from fastapi.staticfiles import StaticFiles

BASE = Path(__file__).parent
FRONTEND = BASE.parent / "frontend"


def load_alerts():
    return json.loads((BASE / "data" / "alerts.json").read_text(encoding="utf-8"))


app = FastAPI(title="水星家纺 异常交易监测")


@app.get("/api/health")
def health():
    return {"status": "ok", "alerts": len(load_alerts())}


# 静态托管必须最后挂载，否则会吞掉 /api 路由
```

```python
import json
from pathlib import Path
from fastapi import FastAPI, HTTPException
from fastapi.staticfiles import StaticFiles

BASE = Path(__file__).parent
FRONTEND = BASE.parent / "frontend"
ALERTS = json.loads((BASE / "data" / "alerts.json").read_text(encoding="utf-8"))

app = FastAPI(title="水星家纺 异常交易监测")


def _summary(a):
    return {
        "id": a["id"],
        "alert_no": a["alert_no"],
        "risk_score": a["risk_score"],
        "level": a["level"],
        "scenario": a["scenario"],
        "summary": a["anomaly_description"]["what"],
        "parties": a["parties"],
        "created_at": a["created_at"],
    }


@app.get("/api/alerts")
def list_alerts():
    return [_summary(a) for a in ALERTS]


@app.get("/api/alerts/{alert_id}")
def get_alert(alert_id: str):
    for a in ALERTS:
        if a["id"] == alert_id:
            return a
    raise HTTPException(status_code=404, detail="alert not found")


@app.post("/api/detect/run")
def run_detection():
    return {"detected": len(ALERTS), "alerts": [_summary(a) for a in ALERTS]}


# 静态托管最后挂载，避免吞掉 /api 路由
app.mount("/", StaticFiles(directory=str(FRONTEND), html=True), name="frontend")
```

```javascript
function showView(name){
  $("view-list").classList.toggle("hidden", name !== "list");
  $("view-detail").classList.toggle("hidden", name !== "detail");
}

function layerTile(label, text){
  return `<div class="layer-tile"><div class="lt">${label}</div><div class="lb">${text}</div></div>`;
}

function renderCard(a){
  const d = a.anomaly_description, t = a.trigger_reasons;
  const cases = a.similar_cases.map(c =>
    `<div class="case"><span class="when">${c.date} · ${c.dept}</span>${c.summary}</div>`).join("");
  const actions = a.recommended_actions.map(x =>
    `<div class="action"><span class="urg urg-${x.urgency}">${x.urgency}</span><span>${x.action}</span></div>`).join("");
  $("card").innerHTML = `
    <div class="card">
      <div class="card-head">
        <span class="big-score score ${scoreClass(a.risk_score)}">${a.risk_score}</span>
        <span class="meta">
          <span class="alert-no">${a.alert_no} · 级别 ${a.level}</span>
          <span class="scenario">${a.scenario}</span>
        </span>
      </div>
      <div class="card-sec">
        <h3>① 异常描述</h3>
        <div class="desc-line"><span class="k">涉及人</span>${d.who}</div>
        <div class="desc-line"><span class="k">时间</span>${d.when}</div>
        <div class="desc-line"><span class="k">事件</span>${d.what}</div>
        <div class="desc-line"><span class="k">背景</span>${d.context}</div>
      </div>
      <div class="card-sec">
        <h3>② 触发原因（三层联动）</h3>
        <div class="layers">
          ${layerTile("规则层", t.rule_layer)}
          ${layerTile("统计层", t.stat_layer)}
          ${layerTile("画像层", t.profile_layer)}
        </div>
      </div>
      <div class="card-sec">
        <h3>③ 相似历史案例（Top ${a.similar_cases.length}）</h3>${cases}
      </div>
      <div class="card-sec">
        <h3>④ 建议动作</h3>${actions}
      </div>
      <div class="card-sec parties">
        <h3>⑤ 涉及方</h3>
        <span>提交人：${a.parties.submitter}</span>
        <span>审批人：${a.parties.approver}</span>
        <span>供应商：${a.parties.vendor}</span>
      </div>
      <div class="card-sec">
        <h3>⑥ 数据溯源</h3><div class="lineage">${a.data_lineage}</div>
      </div>
    </div>`;
}

async function showDetail(id){
  const r = await fetch(`/api/alerts/${id}`);
  renderCard(await r.json());
  showView("detail");
  window.scrollTo(0, 0);
}

$("btn-back").addEventListener("click", () => showView("list"));

loadList();
```

- [ ] **Step 1: 在 app.js 顶部 loadList 之后、`$("btn-back")` 监听之前插入检测动画逻辑**

在 `frontend/app.js` 中 `$("btn-back").addEventListener(...)` 这一行之前插入：
```javascript
function sleep(ms){ return new Promise(r => setTimeout(r, ms)); }

async function runDetection(){
  const box = $("detect-status");
  const btn = $("btn-detect");
  btn.disabled = true;
  $("alert-rows").innerHTML = "";
  box.classList.remove("hidden");
  const steps = [
    "连接鼎捷 ERP / 电商结算数据源…",
    "规则层扫描：重复付款 / 拆单 / 账户变更…",
    "统计层计算：Z-Score / 滑动窗口聚集…",
    "画像层比对：人员 / 供应商行为偏差…",
    "AI 生成告警卡（原因 + 历史案例 + 建议动作）…",
  ];
  for (const s of steps){
    box.innerHTML = `<span class="spinner"></span>${s}`;
    await sleep(650);
  }
  const r = await fetch("/api/detect/run", {method: "POST"});
  const body = await r.json();
  box.innerHTML = `✓ 检测完成：扫描全量交易，发现 <b>${body.detected}</b> 条高风险异常`;
  renderList(body.alerts);
  btn.disabled = false;
}

$("btn-detect").addEventListener("click", runDetection);
```
